# Native game and local Player setup

## Play the prepared local game

Open release/Super Mario Odyssey.app in Finder, or run:

```sh
./scripts/play-odyssey.command
```

This developer launcher uses the prepared game-data/super-mario-odyssey folder.
Keep that local app in the workspace. The standalone app generated by the browser
builder contains its own data and can be copied to Applications.

## Saves and separate instances

The prepared Player save is game-data/super-mario-odyssey/run/save. Launching the
regular app continues that progress. Extra personal slots can be selected with
scripts/play-odyssey.command --slot Elad2. release/Play Fresh Save.command opens
the separate FreshStart slot. Existing backups stay in
game-data/super-mario-odyssey/save-backups/.

The standalone browser-generated app uses Application Support for its own saves,
graphics preferences and logs. Existing persistent profile paths are retained
for compatibility with earlier builds.

Automated Tests use a separate process, port 4318 and a private save/settings
directory under tmp/odyssey/. Each run copies an optional checkpoint into a fresh
private save. Physical input in the Player window cannot alter scripted test input.
Player's manager uses port 4317; tests must never start or stop that instance.

## Controls

| Key | Action |
| --- | --- |
| WASD | Move / left stick |
| Arrow keys | Camera / right stick |
| J / K | A / B: confirm and jump |
| U / I | X / Y: cap actions |
| Q / E | L / R |
| Z / C | ZL / ZR: crouch and ground pound |
| Return / Tab | Plus / Minus |
| Space | Controller shake |
| Command-Q | Quit |
| Control-Command-F | Fullscreen |

Controllers recognized by macOS GameController are supported. Open the game's
Options > Graphics page to change the renderer limit and FPS counter. Simulation
runs at 60 Hz; active gameplay can render uncapped. Display refresh and recording
cadence are separate measurements.

## Develop and record

The [native game harness](../tools/game-harness/README.md) supplies Playwright-style
keyboard and text locators over the native Unix socket. Its browser is the viewer
and recorder. Tests use real native state waits and include titles, action
thumbnails, results and native sound in compressed MP4 recordings.

```sh
bun run --cwd tools/game-harness check
bun run --cwd tools/game-harness start
bun run --cwd tools/game-harness gui
```

Native-window and ScreenCaptureKit tests need explicit user approval. Automated
acceptance uses the isolated headless path. A headless capture does not establish
final native-window presentation correctness.

The runtime is built from pinned [nxnative](https://github.com/seedds/nxnative)
source with scripts/patches/nxnative-odyssey-sdk3.patch and the browser source-shader
patch. Public release builds export the pinned source; the ignored development
checkout may contain experiments. Follow the [browser release guide](browser-release.md)
for the complete source-built runtime and WASM toolchain.
